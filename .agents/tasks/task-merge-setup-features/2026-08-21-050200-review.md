# Branded loading screen and story progress bar (v2)

The v1 review raised four issues: a timeout race redirecting authenticated users on slow networks, a stale `onComplete` closure, an in-flight rAF race on index change, and `onComplete` as a dependency restarting animation. All four are resolved. The loading screen gates now suppress the timeout via a no-op `onTimeout`, the story bar uses a ref for `onComplete` (removing it from the dependency array), and a `cancelled` flag guards post-cleanup invocations.

**Watch for:** Minor timer churn in auth gates from inline `onTimeout` arrow functions (possible, non-blocking). No functional issues remain.

**Verdict**: APPROVED

## High-level view

The timeout race is eliminated by design: all three auth gates pass `onTimeout={() => {}}`, making the 5-second timer a no-op while auth resolves. The `RouteFallback` in `App.tsx` deliberately keeps the default behavior — a lazy-chunk Suspense that hangs for 5 seconds probably indicates a broken session, so redirecting to `/auth` is acceptable there.

The story progress bar now uses `onCompleteRef` to decouple callback identity from animation lifecycle. The dependency array is `[currentIndex, paused, duration]`, so parent re-renders no longer restart the bar. The `cancelled` flag set in cleanup prevents the rAF chain from invoking `onComplete` after the effect is torn down, closing the race between index changes and in-flight animation frames.

## Verification of v1 fixes

**Issue 1 (timeout race):** All three auth gates now render `<AppLoadingScreen onTimeout={() => {}} />`. The timer invokes the no-op instead of navigating; when auth resolves, unmount cancels it.

**Issue 2 (stale closure):** `onCompleteRef` pattern on lines 35-36 of `StoryProgressBar.tsx` ensures the animation loop always invokes the latest callback:

```tsx
const onCompleteRef = useRef(onComplete);
onCompleteRef.current = onComplete;
```

**Issue 3 (in-flight race):** A `let cancelled = false` flag is set to `true` in cleanup. The `animate` function checks it at entry and before calling `onCompleteRef.current`, so a stale rAF scheduled for the previous index bails out immediately.

**Issue 4 (dependency restart):** Dependency array is `[currentIndex, paused, duration]` — `onComplete` removed. Parent re-renders no longer restart animation.

## Timer churn in auth gates

`AppLoadingScreen`'s effect depends on `[navigate, onTimeout, timeoutMs]`. In `ProtectedRoute`, `onTimeout` is `() => {}` — a new reference on every render. The effect re-runs (clearing and re-setting the timer) whenever `ProtectedRoute` re-renders during the loading phase. The only cost is creating/clearing no-op timers, not behavioral correctness.

A ref-based pattern identical to what `StoryProgressBar` already uses would eliminate this:

```tsx
const onTimeoutRef = useRef(onTimeout);
onTimeoutRef.current = onTimeout;

useEffect(() => {
  const id = setTimeout(() => {
    if (onTimeoutRef.current) onTimeoutRef.current();
    else navigate("/auth", { replace: true });
  }, timeoutMs);
  return () => clearTimeout(id);
}, [navigate, timeoutMs]);
```
