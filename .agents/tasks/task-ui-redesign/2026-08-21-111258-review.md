# Premium visual overhaul: design tokens, glassmorphism chrome, and page-level polish

This change replaces the device-frame "phone in a browser" shell with a full-bleed layout, introduces a charcoal/violet design-token system, and applies glassmorphism + micro-animation upgrades to every user-facing surface: navigation, feed, loading screen, auth page, and profile. The approach keeps the component tree intact and limits changes to styling layers — CSS custom properties, Tailwind classes, and Framer Motion props — so behavioral logic is untouched. The build and type-check pass cleanly; existing test results are unchanged.

Watch for: the `activeItem` variable computed in MobileNav is never consumed (confirmed); the AppShell removes device-frame constraints which may break scroll containment on desktop viewports (likely); animated orbs on Auth and LoadingScreen run infinite GPU-composited animations that stack on low-end mobile hardware (likely).

**Verdict**: APPROVED

## High-level view

The AppShell strips its phone-frame wrapper (border, notch, max-width, aspect-ratio) and becomes a simple flex column. For a Capacitor-native app this is correct, but it removes the only scroll-height constraint that prevented the page from stretching unbounded on desktop browsers — worth verifying if a desktop web target still matters.

MobileNav gains a `motion.span` with `layoutId="nav-active-indicator"` that animates between tabs, a gradient-circle Create button, and glassmorphism backdrop. The implementation computes an `activeItem` variable that is never read, leaving dead code in the component.

Auth and LoadingScreen both render multiple absolutely-positioned `motion.div` orbs with infinite keyframe loops (8–12 s cycles). On a Capacitor app targeting mid-range Android, three layered blur + scale animations running simultaneously during page load could spike GPU memory and delay first meaningful paint.

The Profile page replaces the compact inline stats with a vertical-number layout separated by `h-8 w-px` dividers. With four stat columns plus dividers, the row can overflow on narrow viewports (≤320 px) since none of the stat buttons have `min-w-0` or wrapping rules.

The design-token layer migrates from raw hex/opacity classes to semantic CSS custom properties, enabling the existing light-theme and Aurum-theme overrides to propagate consistently across all changed components.

## Dead variable in MobileNav

Lines 28–33 of MobileNav compute `activeItem` by iterating `items` and matching against `loc.pathname`. The result is never consumed — the per-item `isActive` comes from React Router's `NavLink` render prop instead.

```tsx
const activeItem = items.find((item) => {
  if (item.action) return false;
  if (item.end) return loc.pathname === item.to;
  return loc.pathname.startsWith(item.to);
});
// ← never referenced
```

## Animated orbs and reduced-motion

Auth renders three `motion.div` blobs with `blur-[150px]`, each cycling on 8–12 s infinite loops with scale and translate. LoadingScreen adds another three with `blur-[60px]` to `blur-[100px]`. These stack before any interactive content is visible (LoadingScreen is literally the first paint).

No `prefers-reduced-motion` guard exists. On budget Android (which Capacitor targets) compositing three blurred layers during app boot competes with Supabase auth initialization for main-thread time. The fix — wrapping the orbs in a `useReducedMotion()` check from Framer Motion — is trivial.

## Stats row on narrow viewports

The Profile stats row uses fixed `px-5` padding and `h-8 w-px` dividers between four `<button>`/`<Link>` elements:

```tsx
<div className="flex items-center gap-0 pt-2">
  <Link ... className="... pr-5">
  <div className="h-8 w-px bg-border" />
  <Link ... className="... px-5">
  ...
</div>
```

At 320 px viewport width (iPhone SE / Galaxy A series), four columns × ~72 px each = ~288 px minimum, plus four 1px dividers and outer padding pushes past the edge. The container has no `overflow-x-auto` and no wrapping rule, triggering a horizontal scroll on the page body.

## AppShell frame removal and desktop viewport

The old shell constrained content inside a `max-w-[440px] aspect-[9/19.5]` frame. The new shell is `min-h-screen w-full h-full flex flex-col` with no max-width. If this app is also served as a desktop PWA or responsive web app, feed content stretches to the full browser width. Confirm this is intentional or add a `max-w-lg mx-auto` wrapper for non-native contexts.
