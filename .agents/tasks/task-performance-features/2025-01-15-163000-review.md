# Performance and quality infrastructure for Parallax social app

This change adds eight features to Parallax: Vite bundle splitting, infinite scroll with Firestore cursor pagination, client-side image compression and Cloudinary URL transforms, Zod v4 form validation via react-hook-form, error reporting to Firestore, client-side rate limiting, i18n with English/Hindi, and PWA support via a service worker. The work is primarily additive — new hooks, utilities, and library files — with integration points woven into the existing page components (Feed, Discover, Reels, Auth, Compose, EditProfile, Settings).

**Watch for:** The `useInfiniteFirestore` hook's `loadMore` is unstable across renders due to its dependency on `hasMore` state, which will cause the IntersectionObserver effects to re-attach on every pagination event (confirmed). The service worker caches JS/CSS assets by full URL but Vite produces content-hashed filenames, so the cache-first strategy can serve stale bundles after a deploy (likely). The rate limiter's `checkRateLimit` ignores the `actionName` parameter — both branches of the ternary produce the same string (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

Bundle splitting via `manualChunks` is well-segmented — Firebase is further split into auth/storage sub-chunks to stay under the 600KB limit. Any package not explicitly listed falls into a single un-split remainder chunk, which will drift as dependencies grow.

Infinite scroll is implemented via a generic `useInfiniteFirestore` hook that wraps Firestore's `startAfter` cursor pattern with IntersectionObserver sentinels in each page. The hook's `loadMore` callback has a referential stability problem: it depends on `hasMore` state, so every time pagination toggles `hasMore`, all downstream effects and observers re-run. The hook also swallows errors silently, logging to console only.

Image compression uses Canvas API to resize and re-encode as JPEG before Cloudinary upload. The URL transform helpers insert parameters after `/upload/` via string replace — brittle if URLs already contain transformations, but safe given this app controls the upload path. The JPEG-only output silently destroys alpha channels from PNG/GIF sources.

Form validation introduces a custom `zodResolver` to bridge Zod v4's `.issues` API with react-hook-form. The resolver joins issue paths with `.` and assigns to a flat `FieldErrors` map rather than building a nested structure — correct for the flat schemas used here, but will break for nested object schemas.

The service worker uses cache-first for navigation and `.js`/`.css` assets. Because Vite produces content-hashed filenames, the cache accumulates stale assets with no eviction, and after a deploy the SW serves a cached `index.html` referencing JS files not yet in the cache. There is no versioned cache-busting beyond `CACHE_NAME = 'parallax-v1'`.

Rate limiting is client-side only — a UX courtesy with no server-side enforcement. The `authLimiter` (5 attempts/minute) might create a false sense of security against brute-force attacks when it provides no actual protection at the Firebase Auth layer. The `checkRateLimit` helper has a dead-code branch where `actionName` is unused in the toast message.

i18n coverage is partial — only Auth, Feed tabs, and Settings section headers are translated; rows like "Edit profile", "Change password" remain hardcoded English, creating a fragmented experience when switching to Hindi.

## Referential instability in `useInfiniteFirestore`

The `loadMore` callback is wrapped in `useCallback` with `[baseQuery, pageSize, hasMore]` as dependencies. Every time a page is fetched and `setHasMore` is called (even when it stays `true`), `loadMore` gets a new reference. Every page component has an effect like:

```ts
useEffect(() => {
  observer.observe(el);
  return () => observer.disconnect();
}, [hasMore, loading, loadMore]);
```

This tears down and recreates the IntersectionObserver on every pagination cycle, which could cause missed intersections during the teardown window. The fix is to read `hasMore` from a ref inside the callback rather than closing over the state value.

## Service worker staleness and cache growth

With Vite's content-hashed filenames (e.g., `index-Dk3f8x.js`), a deploy produces entirely new filenames. The stale `index.html` in the cache references old hashes, and those old files are found in the SW cache — so stale content is served indefinitely.

The `activate` event cleans caches that don't match `CACHE_NAME`, but since the name is hardcoded to `'parallax-v1'`, bumping it requires a code change and redeploy — the very scenario where staleness is the problem.

```
parallax-v1  →  serves cached index.html referencing index-OLD.js
              →  index-OLD.js found in cache → stale content served
              →  user never sees new code until cache evicted
```

A network-first strategy for navigation (with cache fallback for offline) would be more robust. Hashed assets are immutable by filename, so a network-first fetch for them only hits the network once per unique hash.

## Image compression drops alpha channels

`compressImage` unconditionally exports to `image/jpeg`:

```ts
canvas.toBlob(
  (blob) => { ... },
  "image/jpeg",
  quality
);
```

Any PNG with transparency will get a black background where alpha existed. The skip condition (`file.size <= 100KB`) catches many small PNGs, but larger transparent PNGs (stickers, overlays) will be silently converted. A check for `file.type === 'image/png'` could either skip compression or switch to `image/webp` output.

## Partial i18n coverage

The Settings page translates section headers (`Account`, `Privacy`, `Your data`) but every row title remains hardcoded English ("Edit profile", "Change password", "Login activity"). The Feed page translates tab labels and empty states, but "You're all caught up" is hardcoded. This creates a fragmented multilingual experience where switching to Hindi translates some chrome but not the actionable content.

## Rate limiter security posture

The `createRateLimiter` stores timestamps in an in-memory `Map` per key — not per user, not per resource. All `like` actions share a single limiter regardless of which post is being liked. The limit resets on page reload, and a new tab bypasses it entirely.

The `authLimiter` (5 attempts/minute) provides no protection at the Firebase Auth layer. Firebase's own brute-force protection (if enabled) is the actual control; this client-side limiter should not be relied upon for security.

## Discover page initial load race

```ts
useEffect(() => {
  Promise.all([loadMoreProfiles(), getDocs(...), ...]).then(...)
}, [user?.id]);
```

If the sentinel element is in the viewport on mount (large screens), the IntersectionObserver fires immediately alongside this effect. The `isFetchingRef` guard makes the race technically safe for the first mount, but if the component re-mounts or `user.id` changes, timing alignment between the effect re-run and the observer can produce duplicate page fetches.
