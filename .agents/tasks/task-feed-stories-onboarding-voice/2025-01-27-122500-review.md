# Interest engine, stories migration, onboarding flow, and voice note upload (v2)

Four features in one batch: a client-side feed ranking engine with Firestore interest vectors, a Supabase→Firestore stories migration, a three-step onboarding wizard seeding the interest engine, and a voice-note upload fix switching from a dead Supabase shim to Cloudinary. All five critical issues from v1 have been resolved: the interest vector uses atomic `increment()`, the scoring formula floors engagement velocity at 1, reaction objects no longer include timestamps for proper `arrayUnion` deduplication, onboarding writes use `writeBatch` for atomicity, and `hasUnseen` now checks actual viewer arrays. The two remaining observations from v1 (Cloudinary fallback and feed re-fetch on tab switch) were acknowledged as intentional trade-offs. Watch for: no new blocking issues found in this pass.

**Verdict**: APPROVED

## High-level view

The interest engine's `updateInterestVector` now uses `setDoc(docRef, { [topic]: increment(delta) }, { merge: true })`, eliminating the read-modify-write race without even requiring a transaction. The `scorePosts` formula applies `Math.max(1, ...)` around the engagement numerator, so brand-new posts rank by topic match and recency rather than collapsing to zero.

The onboarding flow wraps all Firestore writes in a single `writeBatch` that commits atomically. The Cloudinary avatar upload runs outside the batch and tolerates failure gracefully — the user gets onboarded without the avatar.

Story reactions write `{ user_id, emoji }` without a timestamp, so `arrayUnion` genuinely deduplicates repeat taps. The `StoriesRail` computes `hasUnseen` from actual viewer arrays, giving the StoryRing gradient semantic meaning.
