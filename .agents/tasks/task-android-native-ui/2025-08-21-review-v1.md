# X/Twitter + Instagram Reels native Android retheme

This change strips the glassmorphism/violet visual identity and replaces it with a dark-mode theme modeled on X (Twitter) — pure black backgrounds, `#1D9BF0` (X-blue) as the primary accent, solid surfaces, no backdrop blurs — along with Instagram-inspired story rings and Reels full-screen layout. The bottom navigation shifts from a 5-item set (Home, Explore, Create, Wallet, Profile) to an X-style set (Home, Search, Spaces, Notifications, Messages), removing the inline create sheet and relying on the floating compose FAB and SideMenu for profile/wallet access. The Reels page drops its For You/Following tab switcher and chrome-dimming timer in favor of a simpler Instagram Reels header. Profile adopts the X layout (cover → overlapping avatar → name/handle/bio → stats → tabs).

Watch for: Dead code in Reels where `onTip` is passed but no UI triggers it (**confirmed**); unused `Sparkles` import in both PostCard and Reels (**confirmed**); compose sheet removed from nav with no equivalent quick-create surface from every screen (**confirmed**).

**Verdict**: APPROVED

## High-level view

The design token overhaul in `index.css` is the foundation: primary hue moves from violet (250°) to X-blue (204°), backgrounds go pure black, all `backdrop-filter` and pseudo-element gloss effects are neutralized to `display: none` or solid fills. The light theme loses its frosted glass surfaces entirely (~130 lines deleted), which will look very plain if the app is ever used in light mode.

The bottom navigation restructure replaces a "create" center button (which triggered `UnifiedCreationSheet`) with a Spaces link, moving the compose surface to the floating FAB in Feed. Wallet and Profile migrate entirely to the SideMenu drawer. All new nav targets (`/live`, `/notifications`, `/messages`) have existing routes, so navigation won't 404. However, the compose FAB lives inside the Feed component — not in AppShell — so it disappears on every other screen.

The Reels page simplifies its chrome: the For You/Following tab switcher, the auto-dim timer, and the Tip action button are removed. The tip infrastructure (`onTip` prop, `TipSheet` render) remains wired but orphaned — the UI button that opens it is now a no-op `MoreHorizontal` icon.

The Profile page removes the cover image gradient overlay that provided text readability over light cover photos. With the avatar and action buttons now overlapping the raw cover edge, light-colored cover images may make UI elements hard to see.

## Orphaned tip infrastructure in Reels

The `ReelItem` component still declares `onTip` in its prop interface. The parent still passes it, and the `TipSheet` is still rendered at the bottom of the Reels component. But the button that previously triggered it has been replaced by:

```tsx
<ActionButton
  icon={<MoreHorizontal className="h-7 w-7 text-white" strokeWidth={1.8} />}
  label=""
  onClick={() => {}}
/>
```

This leaves the full tip flow (state variables, TipSheet mount, prop threading) as dead code that inflates the component and confuses future readers about whether tipping is intentionally disabled or accidentally broken.

## Navigation topology and compose discoverability

The old bottom nav: Home, Explore, **Create** (sheet), Wallet, Profile.
The new bottom nav: Home, Search, **Spaces**, Notifications, Messages.

`UnifiedCreationSheet` is no longer imported or rendered anywhere. Content creation is now reachable only through:
- The floating blue FAB on the Feed page (links to `/compose`)
- Camera icon on the Reels header (links to `/compose/reel`)

The FAB uses `position: fixed` but is rendered inside the `Feed` component, not in `AppShell`. Navigating to any other screen (Messages, Notifications, Profile, Discover) loses the compose affordance entirely. On X, the FAB is globally visible — this implementation doesn't match that pattern.

## Light theme degradation

The `.light .liquid-glass`, `.light .liquid-nav`, `.light .glass`, `.light .glass-strong`, and the multi-layer background gradient on `.light body` are all removed. Light mode now gets only a single `linear-gradient(180deg, ...)` background with flat solid surfaces. If the app supports light mode, this will feel visually stark compared to the rich frosted-glass treatment that existed before. This may be intentional (dark-only Android target), but worth noting if light mode is ever surfaced.

## Profile cover scrim removal

The cover image previously had a bottom gradient overlay:

```html
<div className="absolute inset-x-0 bottom-0 h-24 bg-gradient-to-t from-background/80 to-transparent" />
```

This is deleted. The avatar ring, "Edit" button, and action buttons sit at the cover's bottom edge without any contrast aid. On a white or light-colored cover photo, these elements will be nearly invisible. The avatar has `ring-4 ring-background` (black ring), which helps, but the text labels and icon buttons have no shadow or backdrop.

## Accessibility: nested button in Profile dropdown

In the "not-me" profile variant, a `<button>` wraps a `<DropdownMenu>`:

```tsx
<button type="button" aria-label="More actions" className="...">
  <DropdownMenu>
    <DropdownMenuTrigger asChild>
      <span><MoreHorizontal className="h-4 w-4" /></span>
    </DropdownMenuTrigger>
    ...
  </DropdownMenu>
</button>
```

The outer `<button>` receives clicks but does nothing with them; the dropdown relies on the inner trigger span. This creates a confusing focus/click target for assistive technology. The Radix `asChild` composition typically expects to merge onto a focusable element, not a `<span>` inside an unrelated button.
